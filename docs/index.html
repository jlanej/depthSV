Read-depth association at biobank scale

depthSV

Every genomic bin's sequencing depth is a copy-number dosage. depthSV tests that dosage against phenotypes across a cohort without calling variants first: a technical correction whose components stay in the association model, a ploidy model for the sex chromosomes, and genome-wide thresholds calibrated by permutation rather than assumed.

At a glance

Input

One mosdepth regions file per sample (fixed bins, typically 1 kb), a table of coverage principal components, per-sample median coverage, a phenotype table, and optionally sex.

Unit of work

A genomic region. Every stage after the join takes --region chr1:1-10000000, reads it through the index, and writes one shard. A SLURM array, a WDL scatter and a local loop dispatch the same scripts.

Test

Per bin: linear, logistic or Cox regression of the phenotype on corrected depth, with covariates and the removed PCs in the model. One matrix product per block for the linear path.

Output

Per bin: estimate, standard error, statistic, p, a single-sample leverage share. Per analysis: an exported table, an empirical family-wise threshold, hits with adjusted p, and provenance.

Why read depth

A deletion halves the number of reads that land on it; a duplication adds half again. Sequencing depth is therefore a direct, quantitative readout of copy number at every position of the genome, and it is available for every sample in a sequenced cohort at no extra cost. Copy-number variants account for more base pairs of difference between two genomes than any other variant class, yet most association studies have tested them only after a calling step that decides, per sample, whether a variant is present.

Calling is where the difficulty lives. Breakpoints vary, alleles overlap, multiallelic and mosaic events resist a discrete genotype, and every caller has its own sensitivity profile. Recent work in the UK Biobank turned this around: genotyping copy number from read depth in 5-kb bins across 490,000 genomes and testing those genotypes phenome-wide found that three quarters of the signals were strongest under a plain additive model, and that read depth at 30× is accurate for events of 5 kb and larger across the whole frequency spectrum, including multiallelic repeats and somatic mosaics.1 An independent phenome-wide analysis of the same cohort with called CNVs excluded events under 10 kb and the sex chromosomes entirely, citing variable ploidy.2

depthSV takes the additive model one step further and tests the continuous dosage itself. No genotype clustering, no size floor beyond the bin, and the sex chromosomes stay in through an explicit ploidy model. Two things have to be right for that to work, and they are the substance of the method:

  • Technical structure. Depth varies with GC content, library preparation, sequencing batch and mapping. Read-depth callers have long removed the leading principal components of the depth matrix to absorb this,3,4 and have long known that removing too many also removes real copy-number variation. depthSV keeps the removed components inside the association model, where the algebra requires them, and measures how many to remove against known deletions.
  • Calibrated inference over millions of correlated tests. Bins are not independent, the null is not exactly normal, and a fixed 5 × 10⁻⁸ answers a question about SNPs. depthSV derives its threshold from permutations of the same data, with Bonferroni reported beside it.

The pipeline

Each stage writes to a temporary file, verifies it, indexes it and only then moves it into place with a marker that records every input's identity, every parameter and the driver's own checksum. A rerun with the same inputs skips the unit; a rerun after a changed coverage table, model or version redoes it and says which line differed.

1 · Join

The join turns one file per sample into one matrix per cohort: bins as rows, samples as columns, bgzip-compressed and tabix-indexed so that any later stage can read a region without scanning the file. Every sample's bin coordinates are checksummed during extraction and must agree with every other sample's; a file built on different intervals, or the same intervals in a different order, is refused rather than pasted into the wrong rows. A sample listed twice is refused before anything is written. The result does not depend on batching or the number of workers.

At biobank width the whole matrix is terabytes and no cloud task should copy it. The block form joins about a thousand samples at a time into indexed block matrices; a per-window task then reads its region from every block through the index and pastes the cohort-wide slice for that window alone. The pasted window is byte-identical to the same region of a monolithic join.

2 · Correction

For bin i and sample j, with depth dij, the sample's autosomal median coverage mj, and the expected number of copies cij of that bin in that sample:

rij = max( log₂ [ max(dij, δ) / (mj · cij / 2) ] , −3 )

A diploid bin at the sample's typical depth sits at 0; one lost copy at −1; a gained copy at +0.58. The floor at −3 (a parameter) keeps a zero-depth sample, a homozygous deletion or a mapping gap, from carrying a bin's whole leverage. The expected copies are the ploidy model:

Without the model every sex-chromosome bin is a sex indicator and dominates any phenotype that correlates with sex. With it, a female's chrY is missing rather than the logarithm of nothing, and later stages fit those bins on the samples that have them. Callers such as GATK-gCNV and CNVkit apply the same idea by inferring contig ploidy or doubling male X coverage.5

Removing technical structure

The leading principal components of the depth matrix, computed upstream over the autosomes, capture batch, GC and library effects. The corrected value is the residual of r against the first k of them:

r̃ = (I − QQT) r, Q = orthonormal basis of [1, PC₁ … PCk]

The basis is factorised once per region and every worker reuses it, so a region costs two matrix products. This is the projection qr.resid computes, an order of magnitude faster at width. A bin that is missing for some samples is projected on the complete subset with a basis refactorised for that subset, and that subset is the same for every such bin, so the refactorisation is cached.

How many components. The Marchenko–Pastur or Tracy–Widom count says how many components stand out from noise.6 That is an upper bound on what should be removed, not the answer: the components that carry real copy-number variation sit inside the removed set once k is large enough, and a correction that absorbs the deletions it is meant to expose is worse than one that leaves some batch structure in. The recommended procedure corrects a set of known deletions at several values of k and compares carriers with non-carriers on the corrected depth (AUC, log₂ shift). Recovery plateaus, then erodes; take the start of the plateau. The worked example implements this against the 1000 Genomes SV callset.

3 · Association

Per bin, the model is a regression of the phenotype y on the corrected depth with covariates Z and the same k coverage PCs the correction removed:

y = α + β r̃ + Zγ + Σl≤k θl PCl + ε

The PCs belong in the model. Residualising depth against PC₁…PCk and then testing without them deflates every test by roughly 1 − R²(y ~ PCs), and biases any bin correlated with a covariate that itself correlates with a PC, which is every sex-chromosome bin once sex is a covariate. With the PCs on both sides the projection is identical on both sides and the Frisch–Waugh–Lovell theorem makes the test exact. In simulation this moves λ from 0.51 or 1.81 to 0.99. The analysis stage therefore refuses to run a PC-corrected matrix without the PC table.

Linear
The design [1, Z, PCs] is factorised once per worker. The phenotype is projected on its orthogonal complement once; a whole block of bins is projected with one matrix product; and β̂ = ⟨r̃⊥, y⊥⟩ / ‖r̃⊥‖² with the residual degrees of freedom of the full model. This agrees with lm() to 10⁻¹⁴ and is what makes a genome-wide sweep one matrix product per block rather than one fit per bin. Options: a rank-based inverse-normal transform of the response, which protects type I error and power for non-normal traits,7 and heteroskedasticity-robust (HC1) standard errors.
Logistic
The design is built once and only the depth column changes, so each bin is the same IRLS glm() would run. Under complete separation the Wald statistic collapses toward zero (Hauck–Donner), so the likelihood-ratio p-value and a convergence flag are reported beside it; the null deviance is computed once. A binary response must be coded 0/1, TRUE/FALSE, or as two labels with the case named explicitly; other codings are refused rather than guessed, and phenotypes with fewer than 20 cases or controls are refused up front.
Cox
Per bin with coxph(), the PCs added to the formula, a convergence flag, and robust variance on request.
Per-bin quality control
A bin is skipped when fewer than --min-obs samples have it, when its depth does not vary, or when one sample carries more than --max-share (default one half) of the residualised depth's sum of squares. That share, MAXSHARE, is reported on every row. It is the read-depth analogue of a minor allele count of one: a test carried by one participant. At 3,000 samples a single heterozygous deletion carrier is kept; a single sample three log₂ units from everyone else is not.
Missing samples
A bin whose depth is missing for some samples, chrY in females under the ploidy model, is fitted on the samples that have it with the design refactorised for that subset. Nothing is imputed.

Genome-wide significance

With a million or more bins, adjacent ones correlated, and a null that is only approximately normal, the effective number of tests is unknown and a borrowed SNP threshold is a guess. The linear path being a projection makes the honest alternative cheap. For each of B permutations the analysis stage permutes the covariate-adjusted response, projects it again (the Freedman–Lane scheme, which controls error rates well in the presence of nuisance covariates8), computes every bin's statistic with one extra matrix product per block, and keeps the largest |t| in the shard. Every shard uses the same seed, so the shard maxima fold into one genome-wide maximum per permutation.

The export step then reports, at level α:

  • the empirical family-wise threshold: the k-th largest permutation maximum with k = ⌊α(B+1)⌋ (Westfall–Young max-T),9 so B ≥ 19 at α = 0.05, and the p-value it corresponds to;
  • the effective number of tests that threshold implies, Meff = log(1 − α) / log(1 − pthr), for comparison with the bin count;
  • the Bonferroni threshold beside it, and the hits at each, every hit carrying its adjusted p, (1 + #{maxima ≥ |t|}) / (B + 1).

The permutation statistic is the classical t; the robust option changes the reported standard error, not the permutation distribution. Cost is one extra product of a bins × samples block with a samples × B matrix. Measured single-threaded at 50,000 samples, 100 permutations cost about as much as the projection itself and 500 about four times it, against a parse step that dominates both; at 500,000 samples the permuted responses occupy 0.4 GB per worker at B = 100 and 2 GB at B = 500. A few hundred permutations suits cohorts of thousands; at biobank width 100 is the sensible default and the Bonferroni line is always reported.

Outputs and what a finding looks like

One row per tested bin per analysis, bgzip-compressed and indexed, with the columns below. The export concatenates shards in genome order over the whole region list, refuses to proceed if any region has no finished shard, and drops rows whose counts fall below a floor (20 by default, the All of Us dissemination limit).

Because every bin is tested, a real event appears as a run of adjacent significant bins spanning its extent, with the effect flat across the run; the correction statistics written per region give the pre- and post-correction spread of each bin for inspection.

Classes of result

  • Common dosage effects. A deletion or duplication segregating at a few percent whose carriers shift a quantitative trait: the additive model that carried three quarters of the signals in the UK Biobank read-depth study.1
  • Multiallelic and repeat loci. Amylase, mucin and defensin copy number vary over many states; a continuous dosage test uses all of them at once, where a biallelic genotype cannot.
  • Mosaic and somatic events. Clonal deletions present in a fraction of cells show as fractional dosage in the samples that carry them, visible to depth and invisible to genotype-based tests.
  • Sex-chromosome events under the ploidy model, which most published scans exclude.
  • Artefacts to expect. Nuclear insertions of mitochondrial sequence attract mitochondrial reads and track mitochondrial copy number; low-mappability regions track library properties. The single-sample share, the permuted and structured nulls, and the pre/post correction statistics are the tools for telling these apart.

Not visible by construction: balanced rearrangements, events well below the bin size, and effects that are not monotone in copy number.

Calibration and checks

A sweep is only as good as its null. Three things are checked routinely, and the worked example turns each into an assertion that fails the run:

  • Genomic control λ of a permuted phenotype, judged on autosomal bins because every sex-chromosome bin carries the same sex vector.
  • A coverage-PC null. The leading PC plus noise as the phenotype: a test that failed to condition on the removed components would be deflated to λ ≈ 0.5 here, a correct one sits at 1.
  • A structured null drawn from the kinship matrix, y ~ MVN(0, h²·2K + (1 − h²)I), which a permuted phenotype cannot show, run over everyone and over the unrelated set.

The test suite (97 checks, synthetic data with known deletions, sex chromosomes, zero-depth and single-outlier bins) asserts on the numbers rather than on exit codes: the injected association is recovered with the estimate lm() and coxph() give, the PC-driven null stays calibrated, the ploidy model centres chrX for both sexes and fits chrY on males only, a permutation maximum equals an independent recomputation under the documented contract, and outputs are byte-identical between a host and the container.

Running it

Four scripts, one region at a time. On a cluster, an array task per region; in the cloud, a WDL scatter with the same scripts inside a published image; on a workstation, a loop. Nothing in the pipeline knows which.

scripts/join.sh    --manifest mosdepth.input.txt --out work/join
scripts/regions.sh --matrix work/join/depth.matrix.txt.gz --window 10000000 --sizes hg38.chrom.sizes > regions.txt
scripts/correct.sh --region chr1:1-10000000 --ndim 40 --sex phenotypes.tsv --par conf/par.grch38.bed
scripts/analyze.sh --corrected work/corrected/corrected_ndim40.chr1_1-10000000.txt.gz \
                   --pheno-manifest analyses.tsv --pcs svd.pcs.txt --perms 100 --region chr1:1-10000000
scripts/export.sh  --results work/assoc --regions regions.txt --pheno-manifest analyses.tsv --out work/export

Two WDL workflows ship for Cromwell and dxCompiler: one that starts from a joined matrix, and the block form for biobank width in which no task sees the whole matrix. Inputs can be streamed rather than copied. The container is built for linux/amd64 on every release tag and published with its digest, so a run can be pinned to the exact image. Every export summary records the version and commit it was made by.

Limitations and roadmap

  • Relatedness. Regression with covariates does not model kinship. With relatives in the cohort, run the sweep on the unrelated set as the primary result and use the structured null to quantify what relatedness does to the rest; for biobank-scale cohorts a mixed-model engine is the standard, and depthSV's hand-off to one is not yet validated.
  • Rare binary outcomes. The per-bin Wald and likelihood-ratio tests are fine for balanced traits; unbalanced case counts need a saddlepoint-corrected score test.
  • Non-monotone models. Dosage-sensitive and recessive patterns need integer copy-number genotypes; a continuous test cannot fit them.
  • Scale of the join. The monolithic join is a single-node job; the block form is the biobank path.
